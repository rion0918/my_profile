# スマホのフリック移動（2026-10-25）

スマホの一本指操作を、視点の移動から人物の移動へ変更した。指を置いた地点から滑らせた方向へ進み、指を離すと止まる。短いタップは従来どおり、地面への経路移動や館・作品の選択に使う。

- 10px以内の揺れは移動として扱わない。動かし始めた後も、指を開始点へ戻せば停止し、別の方向へ動かせばその場で向きを変えられる。
- カメラの向きと地面の見え方から方向を変換する。縦・横・斜めを同じ速度で移動し、通常視点と全体表示の両方に対応する。
- 徒歩は既存の速度・常ダッシュ・浅瀬・段差・衝突判定を使う。自転車も既存の物理制御で指の方向へ曲がり、指を離すと停止する。
- 操作中だけ、触り始めた場所に小さな方向ガイドを表示。位置は直接更新し、入力のたびにReactの状態更新や新しいアニメーションループを起動しない。指を離した後の惰性移動は加えない。
- 二本指へ切り替えると人物の移動を止め、見渡し・ピンチ拡大縮小に使う。倍率はジェスチャー開始時を基準に求め、拡大上限付近で二本指を平行移動しても倍率がずれないようにした。
- 指の解放、ブラウザによる操作のキャンセル、ポインター捕捉の喪失、フォーカス離脱、非表示、館内の本文表示では入力を解除する。古いタッチの解放で移動や選択を再開しない。
- マウスのドラッグ・ホイール・地面クリック、キーボード、既存の8操作のHUDは維持。街の案内と読み上げ用の説明にスマホ操作を追記した。
- 自動再生が止められている場合も、フリック後の指の解放をBGMの開始操作として扱う。BGMボタンをOFFにした状態は維持する。

## 確認

`world-touch.test.mjs`で、指の揺れ・8方向・斜めの速度・通常／全体表示の射影を検証する。

`tests/browser/world-touch.js`では、変更前の一本指操作で人物が0mしか動かないことを確認した。変更後は390×844（通常画質）、320×568（低設定・動きを減らす）、844×390（横向き・動きを減らす）で、指の方向への移動・解放時の停止・常ダッシュを確認。

`world-touch-gestures.js`はネイティブのタッチイベントで、移動中の反転・開始点へ戻した時の停止・二本指の拡大と平行移動・キャンセル・捕捉の喪失・フォーカス離脱・タップ移動・本文表示中の停止・自転車・館の上からのフリックとタップ選択を確認する。`world-touch-audio.js`では、初回の音声再生を拒否する状況を再現し、クリックを伴わないフリックからも再生を再試行することをREDから確認した。

記録はローカルの`output/playwright/touch-*.txt`と`touch-*.png`。ブラウザ検証はChromiumのタッチエミュレーションであり、スマホ実機やSafariでの操作感は未検証。

単体テスト96件・型チェック・本番ビルドが成功。既存の`world-ux.js`、`world-hud.js`、`world-halls.js`、`world-ux-loading.js`、`hall-navigation.js`、`security.js`で、マウス・キーボード・8操作のHUD・ツアー・履歴・URL・読み込み失敗・6館への入館・BGM・CSPも確認した。

axeでPC・スマホ縦横の4画面サイズ×入口・探索・画質設定・地図・館内・通常表示の24状態を検証し、対象WCAGルールの検出0件。QA専用コンテキストだけで検査スクリプトを許可し、製品のCSPは変更していない。

390×844・CPU 4倍低速化で、指を滑らせて保持した5秒間の実描画は通常画質59.69FPS、低設定59.60FPS。p95の描画間隔は24.1ms／17.6ms、最大57.8ms／50.9ms。ネイティブのrAFと`performance.now()`でメイン画面への描画だけを数え、検証用の時計による間隔の変更は使わない。結果は`output/playwright/touch-check-touch-frame-rate.txt`。
